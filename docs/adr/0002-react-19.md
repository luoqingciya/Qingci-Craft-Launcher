# ADR-0002：前端采用 React 19

- 状态：已接受
- 日期：2026-10-24
- 决策者：@luoqingciya

## 背景

Tauri 前端可选任意 Web 框架。项目定位为"轻量"，初步倾向编译期框架（Svelte 5），因其产物显著更小。

## 决策

采用 **React 19 + TypeScript + Vite + Tailwind CSS v4**。

## 理由

1. **体积代价可量化且可接受**：React 19 + ReactDOM 经 gzip 约 45 KB，加上应用代码与路由，首屏预算定为 150 KB gzip。前端资源最终压缩进安装包，相对 12 MB 的安装包目标，影响约 1.5%，不构成瓶颈；真正的体积大头是图标、字体与 Rust 二进制。
2. **可维护性优先**：启动器界面会持续演进（版本列表、实例管理、账号、设置、控制台），React 的生态、类型定义质量、以及遇到问题时可检索的资料量，对长期维护的价值高于一次性节省的 100 KB。
3. **人才与协作成本**：React 是当前最通用的前端技能，降低未来协作门槛。
4. **与 Tauri 集成成熟**：官方示例与社区模板以 React 为主，IPC 封装与状态管理的既有方案更多。

## 后果

- 首屏体积预算从 60 KB 上调至 150 KB gzip，并在 CI 中对该预算做断言。
- 需要做路由级代码分割（`React.lazy`），避免把设置页、控制台等非首屏代码打进主包。
- 禁用重量级 UI 组件库的全量引入，图标按需引入。

## 替代方案

- **Svelte 5**：产物更小（约 10–15 KB gzip）、无 VDOM 运行时开销，但生态与协作面较窄。
- **SolidJS**：体积与性能均优，生态规模介于两者之间，风险在于长期维护活跃度不确定。
